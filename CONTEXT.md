# Контекст проекта RiveSkia

Документ для передачи агенту, продолжающему работу над проектом.

---

## Что это за проект

Rive-рантайм для .NET/Avalonia, рисующий через SkiaSharp.

**Зачем понадобился.** У Rive нет живого C#-рантайма. Единственный существующий — [rive-app/rive-sharp](https://github.com/rive-app/rive-sharp) — заброшен (последний коммит январь 2025), рассчитан на UWP и пришпилен к старому коммиту rive-cpp через файл `.rive_head`. Файлы из современного редактора он не открывает: формат `.riv` версионируется, и с тех пор появились text, data binding, layouts, feather, Luau-скриптинг.

**Что сделано вместо этого.** Своя связка поверх актуального [rive-runtime](https://github.com/rive-app/rive-runtime): нативная шимка транслирует команды рендерера Rive в вызовы SkiaSharp, а Avalonia показывает результат. Работает, проверено на реальных файлах, сравнено с эталонным плеером Rive.

---

## Архитектура

Три слоя:

1. **`rive.lib` (C++)** — ядро Rive как есть, не модифицируется. Парсит `.riv`, крутит стейт-машины, обходит дерево артборда и вызывает методы абстрактного `rive::Renderer`. Само не рисует.

2. **`rive_shim.dll` (C++)** — реализует `rive::Renderer`, `rive::Factory`, `RenderPath`, `RenderPaint`, `RenderShader`. Каждый вызов транслирует в указатель на функцию, ведущий в C#. Геометрия копится в `RawPath` и отдаётся наружу целиком, а не по одной команде.

3. **`RiveSkia.Avalonia` (C#)** — принимает вызовы и переводит в `SKCanvas`. Пути кэшируются по id: геометрия тянется из натива один раз и переиспользуется как `SKPath`.

**Почему именно так.** Линковать Skia в C++ нельзя — в процессе уже загружена `libSkiaSharp` от Avalonia, вторая копия Skia дала бы конфликт символов. Поэтому вся отрисовка живёт в управляемом коде, а C++ только диктует.

## Критичные детали сборки

**Архитектура.** Всё должно быть x64. Developer PowerShell по умолчанию открывается в x86-окружении, и тогда линковка падает с невнятными ошибками про `__thiscall` и `LNK4272`. `build.ps1` проверяет `$env:VSCMD_ARG_TGT_ARCH` и при необходимости переинициализирует окружение через `Enter-VsDevShell -DevCmdArguments "-arch=x64 -host_arch=x64" -SkipAutomaticLocation`.

**Флаги должны совпадать с ядром.** Шимка собирается с `/MT /GR- /EHs-c- /std:c++17` и дефайнами `WITH_RIVE_TOOLS WITH_RIVE_TEXT RIVE_CANVAS WITH_RIVE_LAYOUT RIVE_ORE RELEASE NDEBUG NOMINMAX RIVE_WINDOWS _USE_MATH_DEFINES _HAS_EXCEPTIONS=0 YOGA_EXPORT=`. Расхождение хотя бы в одном меняет раскладку классов в заголовках и даёт порчу памяти вместо ошибки компиляции.

**Force-include.** Нужны `/FIrive_png_renames.h /FIrive_harfbuzz_renames.h /FIrive_yoga_renames.h` — ядро собрано с переименованием символов зависимостей.

**Порядок сборки.** После правки C++ сначала `native\build.ps1`, потом `dotnet build`/`dotnet pack`. Иначе в пакет уедет старая нативная библиотека.

**Сборка ядра Rive** требует GNU make и `python3` в PATH (генерация шейдеров), плюс Git for Windows с unix-утилитами (скрипту нужен `sh.exe`).

## Что работает

- Загрузка `.riv`, перечисление артбордов и стейт-машин
- Инстансы артборда и стейт-машины, `advanceAndApply`
- Векторная геометрия: заливки, обводки, толщина, join/cap
- Клипы
- Прозрачность, включая вложенную через `modulateOpacity`
- Линейные и радиальные градиенты
- Вписывание через `Fit::contain` + `Alignment::center`
- Живая анимация в Avalonia через `ICustomDrawOperation` + `ISkiaSharpApiLeaseFeature`
- Сборка NuGet-пакета с нативной dll в `runtimes/win-x64/native/`

## Что не сделано

| Возможность | Текущее поведение |
|---|---|
| Растровые изображения | `decodeImage` возвращает `nullptr`, `drawImage` пустой |
| Меши и кости | `drawImageMesh` пустой |
| Режимы наложения | значение читается, но не применяется — всё `SrcOver` |
| Feather / размытие | значение читается, не применяется |
| Интерактив | `pointerDown/Move/Up` есть в ядре, наружу не проброшены |
| Выбор артборда/машины | всегда индекс 0 |
| Управление входами | нет API для `SetBool`/`SetNumber`/`FireTrigger` |
| Кроссплатформенность | шимка только под Windows |

## Известные проблемы

**Кэш путей не очищается.** `_paths` в `RiveScene` растёт бесконечно. В нативной части деструкторы `ShimPath`/`ShimPaint`/`ShimShader` убирают себя из карт, но C# об этом не знает. Нужен колбэк `onPathDestroyed(id)` из деструктора, по которому C# выбросит `SKPath` из словаря.

**Фиксированный шаг анимации.** Таймер тикает каждые 16 мс и всегда передаёт `1f/60f`, независимо от реально прошедшего времени. Из-за этого анимация подрагивает. Лечится `Stopwatch`:

```csharp
var now = _clock.Elapsed;
var dt = (float)(now - _last).TotalSeconds;
_last = now;
_scene.Advance(Math.Min(dt, 0.1f));
```

**`defaultStateMachine()` может вернуть null.** Встречается на реальных файлах, где машина по умолчанию не помечена. Обязателен фолбэк на `stateMachineAt(0)` — он уже реализован.

**Артборд обрезает содержимое.** Если персонаж выходит за границы артборда, низ будет срезан. Это штатное поведение Rive, эталонный плеер ведёт себя идентично. Не пытаться «чинить».

## Отладка

**Эталонный плеер** — главный инструмент проверки. Работает на том же ядре, что и библиотека:

```powershell
C:\Users\ShaboldaV\source\repos\rive-runtime\tests\out\release\player.exe -b d3d путь.riv
```

Флаг `-b d3d` обязателен: по умолчанию плеер просится в Vulkan, а SDK не установлен. Доступны `d3d`, `d3d12`, `gl`.

Если у плеера картинка правильная, а в библиотеке нет — значит упёрлись в нереализованную возможность. Если одинаково — так задумано в файле.

**Консольный тест** `cs\ShimTest` рендерит один кадр в PNG без Avalonia. Удобен для проверки чисто рисующей части.

## Уроки, которые дорого дались

1. **Проверять гипотезу эталоном раньше, чем чинить.** История с «уезжающим» медведем: полчаса ушло на DPI, `LocalClipBounds` и вёрстку, а оказалось, что эталонный плеер рисует ровно так же — бага не было.

2. **`rcp` нужно удерживать.** `ShimPaint::shader()` сначала брал из `rcp` только id и отпускал — объект удалялся, в карте оставался висячий указатель, программа падала через раз. Поле `rive::rcp<rive::RenderShader> shaderRef` решило.

3. **Делегаты нужно удерживать от GC.** Нативная сторона хранит голые указатели на функции. Локальная переменная с `Callbacks` уезжает под сборку прямо посреди отрисовки. В `RiveScene` это поле класса.

4. **x86-окружение маскируется под что угодно.** Ошибки вида «undefined symbol `_DllMainCRTStartup`» и `__thiscall` в искажённых именах — всегда про разрядность, а не про отсутствующие библиотеки.
